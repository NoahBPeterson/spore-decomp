# Slice s009dc760 (gold4 slice 102) — animation curve / spline family

## Flags
/O2 /MD /Gy /EHsc /TP /arch:SSE   (confirmed: reproduces the 3 byte-exact wrappers)

## Overview
Hermite / Catmull-Rom spline tracks stored as stride-based record vectors
(`{begin, end}` int pairs).  Every track flavour is one of three shapes:

| shape | stride | components | comp offsets | mode byte | tangent slot | vtbl |
|-------|--------|-----------:|--------------|-----------|--------------|------|
| A     | 0x44   | 3          | +8/+0xc/+0x10| +0x1d     | +0x18        | 0x1447cc0 |
| B     | 0x58   | 1          | +8..+0x14    | +0x14/+0x15| +0xc         | 0x1447cc4 |
| C     | 0x1c   | 1          | +8           | +0x14/+0x15| +0xc         | 0x1447cc8 |

Common track record: `{ int count; char* data; }` at offset 0 (so `o[0]`,
`o[1]`, and `count = (o[1]-o[0]) / stride`).

Key record (per flavour): `int time` at +4 (`cvtsi2ss` compare key); value(s)
at +8..; `u8 mode` (low 2 bits, `& 3`) selects the tangent rule:
  0 = auto (finite-difference / Catmull-Rom),
  1 = linear (v - vprev),
  2 = flat (0),
  3 = explicit (stored tangent at the slot).

Result record: `void* vtbl; int time; float comps...` then mode/flag bytes.

## Byte-exactness notes
3/15 byte-exact: 009dcc50, 009dd0c0, 009dd440 (the three wrappers).
The dominant blocker for the rest is that the originals were compiled with
**SSE scalar float** (`movss`/`comiss`/`cvtsi2ss`/`divss`), while
`/arch:SSE /fp:precise` emits **x87** (`fld`/`fcompi`/`fild`/`fdiv`).
`/fp:fast` switches the searches to SSE but *shrinks* the code below the
original size (original has `/fp:precise`-style redundant ops) and breaks the
three wrappers that currently match.  The record copiers (009dd530/5b0) also
use a `rep movsd` tail that a plain dword-loop source does not reproduce.
